# خطة تحسينات «Guess the Language»

خطة تنفيذ لكل التحسينات المقترحة، مرتّبة حسب الأثر والتبعية. كل ميزة فيها: الهدف، الملفات/الجداول المتأثرة، خطوات التنفيذ، تقدير الجهد، والمخاطر.

**مقياس الجهد:** `S` = لمسة سريعة · `M` = جلسة مركّزة · `L` = عدة جلسات.

**المبادئ:**
- كل تغيير سيرفر عبر `apply_migration` + انعكاسه في `supabase/*.sql`.
- كل نص جديد يضاف بمفتاحين i18n (EN + AR) في `src/renderer.js`.
- لا أصول خارجية (CSP): الأصوات تُولَّد بـ WebAudio، الصور تُرسم بـ Canvas.
- كل كتابة سيرفر **best-effort** (catch/تجاهل) حتى لا تكسر اللعب.
- بعد كل تعديل على renderer.js: `node --check` ثم `pnpm run build:web` ثم `electron test/smoke-all.js`، ثم رفع النسخة + كاش الـ SW.

## 0) أساس مشترك — تعديلات قاعدة البيانات (ينفَّذ أولًا)

عدة ميزات تعتمد على هذي الإضافات، فننفّذها دفعة واحدة.

**توسيع جدول `player_stats`:**
```sql
alter table player_stats
  add column if not exists xp            bigint  not null default 0,
  add column if not exists level         int     not null default 1,
  add column if not exists day_streak    int     not null default 0,
  add column if not exists best_day_streak int   not null default 0,
  add column if not exists last_play_date date,
  add column if not exists achievements  jsonb   not null default '[]'::jsonb;
```

**جدول التحدّي اليومي:**
```sql
create table if not exists daily_scores (
  id bigint generated always as identity primary key,
  day date not null,
  player text not null,
  score int not null,
  created_at timestamptz not null default now(),
  unique (day, player)
);
create index if not exists daily_scores_day_score on daily_scores (day, score desc);
```

**RPC موحّد للتقدّم** (يحدّث xp/level/streak/achievements ذرّيًا):
```sql
create or replace function record_progress(
  p_player text, p_seconds int, p_multiplayer bool, p_won bool,
  p_xp int, p_correct int, p_perfect bool
) returns jsonb ... security definer;
```
يرجّع `{ level, xp, day_streak, new_achievements[] }` عشان الواجهة تعرض التهنئة.

- **الملفات:** `supabase/schema.sql` (مرآة) + migration.
- **الجهد:** M · **مخاطر:** منخفضة (كله إضافات، لا كسر للموجود؛ الصفوف القديمة تأخذ الافتراضيات).

## المرحلة 1 — لمسات سريعة (Quick Wins) ⚡

### 1.1 إظهار الشرح بشكل ثابت (أعلى قيمة تعليمية)
- **الهدف:** الشرح حاليًا في توست يختفي بسرعة. نعرضه بثبات في `#feedback-panel` (موجود وغير مستخدم) طوال وقت المراجعة.
- **الملفات:** `renderer.js` (`resolveCurrentQuestion`/`showToast` مكان الشرح، سطور ~1756–1908 و~3601–3648)، `styles.css` (تنسيق اللوحة).
- **الخطوات:**
  1. عند حسم السؤال: املأ `#feedback-panel` بـ (صح/غلط + الإجابة الصحيحة + الشرح) وأزل `hidden`.
  2. أخفِه في `nextQuestion`.
  3. أبقِ التوست للحركة السريعة أو استبدله باللوحة.
- **الجهد:** S · **مخاطر:** منخفضة.

### 1.2 اختصارات لوحة المفاتيح (1–4 للإجابة، Enter=التالي)
- **الهدف:** لعب أسرع على الكمبيوتر.
- **الملفات:** `renderer.js` (مستمع `keydown` عام يربط الأرقام بأزرار الخيارات الظاهرة)، `index.html`/`styles.css` (شارة رقم صغيرة على كل خيار).
- **الخطوات:** ربط `1..4`/`a..d` بنقر زر الخيار المقابل، و`Enter`/`Space` لـ Next، مع تجاهل الحقول النصية.
- **الجهد:** S · **مخاطر:** منخفضة (احذر تعارض مع حقل الاسم).

### 1.3 مؤثّرات صوتية فعلية + اهتزاز
- **الهدف:** الإعداد «Sound effects» موجود بلا أصوات فعلية.
- **الملفات:** `renderer.js` (مولّد `beep(freq,dur)` بـ WebAudio؛ نغمات صح/غلط/عدّ تنازلي/انتهاء)، ربط بإعداد الصوت الحالي.
- **الخطوات:** دالة صوت صغيرة، استدعاؤها في الحسم والمؤقّت؛ `navigator.vibrate` على الجوال.
- **الجهد:** S · **مخاطر:** منخفضة (احترم كتم الصوت وتفاعل المستخدم أولًا لسياسات الautoplay).

### 1.4 ألوان صديقة لعمى الألوان
- **الهدف:** عدم الاعتماد على أحمر/أخضر فقط.
- **الملفات:** `styles.css` + `renderer.js` (إضافة أيقونة `✓`/`✗` ونمط شكل مختلف للصح/الغلط).
- **الجهد:** S · **مخاطر:** لا شيء.

> **حزمة المرحلة 1 = إصدار واحد** (كلها واجهة/عميل، بلا سيرفر). ابدأ بها.

## المرحلة 2 — التقدّم والعودة (تعتمد على الأساس 0)

### 2.1 نظام XP والمستويات
- **الهدف:** إحساس تقدّم دائم في البروفايل.
- **الملفات:** `renderer.js` (`levelFromXp(xp)` بمنحنى، شريط تقدّم في البروفايل + شارة مستوى بجانب الاسم)، `record_progress` RPC.
- **الخطوات:**
  1. XP لكل جولة = دالة في النقاط + الدقّة + مكافأة الجولة الكاملة.
  2. منحنى مستوى (مثلًا `level = floor(sqrt(xp/100))+1`) + ألقاب.
  3. عرض «المستوى X · شريط للمستوى القادم» في `#player-card-profile-stats`.
- **الجهد:** M · **مخاطر:** متوسطة (توازن المنحنى — قابل للضبط لاحقًا).

### 2.2 الإنجازات/الشارات
- **الهدف:** أهداف تحفيزية.
- **الملفات:** `renderer.js` (تعريف `ACHIEVEMENTS[]` = id/شرط/اسم/أيقونة + i18n)، البروفايل (شبكة شارات)، `record_progress` (تخزين المفتوحة في `achievements jsonb`)، توست تهنئة عند الفتح.
- **أمثلة:** أول فوز · سلسلة ١٠ · جولة كاملة ١٠٠٪ · ١٠٠ لعبة · لعب كل الأوضاع · صدارة #1.
- **الجهد:** M · **مخاطر:** منخفضة.

### 2.3 سلسلة الأيام 🔥
- **الهدف:** عودة يومية.
- **الملفات:** `record_progress` (مقارنة `last_play_date` بـ اليوم: متتالي → +1، فجوة → إعادة)، البروفايل + الرئيسية (عرض «🔥 N يوم»).
- **الجهد:** S (بعد الأساس) · **مخاطر:** منخفضة (انتبه للمناطق الزمنية — استخدم UTC ثابتًا).

## المرحلة 3 — التحدّي اليومي (أعلى أثر على العودة)

### 3.1 التحدّي اليومي + ليدربورد يومي
- **الهدف:** نفس ١٠ أسئلة للجميع كل يوم، بليدربورد خاص باليوم.
- **الملفات:** `renderer.js` (اختيار حتمي للأسئلة من بذرة = التاريخ عبر PRNG، فلا حاجة لتخزين الأسئلة)، `daily_scores` (جدول)، الرئيسية (بطاقة «تحدّي اليوم» + حالة «لعبت/لم تلعب»)، شاشة نتائج بليدربورد يومي.
- **الخطوات:**
  1. `dailySeed()` من تاريخ UTC → خلط ثابت لبنك مدمج → ١٠ أسئلة.
  2. منع إعادة اللعب لنفس اليوم (unique day+player)، عرض نتيجة اليوم.
  3. ليدربورد يقرأ `daily_scores?day=eq.<today>&order=score.desc`.
- **الجهد:** L · **مخاطر:** متوسطة (الحتمية عبر الأجهزة، منع التكرار).

## المرحلة 7 — توسيع بنك الأسئلة (المحتوى) 📚

مستقلّة عن باقي المراحل وتقدر تجري بالتوازي في أي وقت (مخاطرها شبه صفر — بيانات فقط).

### الوضع الحالي (المصدر: `src/data/*.json`، تُحمّل عبر `main.js:80` / `preload getQuestions`)

| البنك | الملف | العدد | الصيغة |
|-------|-------|-------|--------|
| Programming Languages | `questions.json` | 383 (15 لغة) | خمّن اللغة |
| Cybersecurity | `questions-cyber.json` | 132 | اختيار من متعدّد |
| DevOps | `questions-devops.json` | 92 | اختيار من متعدّد |
| Networking | `questions-network.json` | 89 | اختيار من متعدّد |
| Game Dev | `questions-gamedev.json` | 73 | اختيار من متعدّد |
| Problem Solving | `questions-algo.json` | 84 | أكمل الفراغ |
| **الإجمالي** | | **853** | |

توزيع صعوبة اللغات حاليًا: easy 103 / medium 175 / hard 105 (متوازن نسبيًا). الأبناك الأصغر (gamedev/network/devops) هي الأولى بالإضافة.

### الصيغ الثلاث (يجب الالتزام بها حرفيًا)

**1) خمّن اللغة** (`questions.json`) — الخيارات تُولَّد وقت التشغيل من لغات أخرى:
```json
{ "id": 384, "correctLanguage": "Rust", "difficulty": "medium",
  "codeSnippet": "fn main() { println!(\"hi\"); }",
  "explanation": { "en": "…", "ar": "…" } }
```

**2) اختيار من متعدّد** (cyber/devops/network/gamedev) — `answer` يجب أن يطابق أحد `options`:
```json
{ "id": 133, "category": "docker", "difficulty": "easy",
  "codeSnippet": "docker ps -a",
  "question": { "en": "…", "ar": "…" },
  "options": ["A","B","C","D"], "answer": "A",
  "explanation": { "en": "…", "ar": "…" } }
```

**3) أكمل الفراغ** (`questions-algo.json`) — `accept[]` بدائل مقبولة (تطبيع حالة/مسافات):
```json
{ "id": 85, "category": "python", "difficulty": "medium",
  "codeSnippet": "for i in ____(10):",
  "question": { "en": "…", "ar": "…" },
  "answer": "range", "accept": ["range"],
  "explanation": { "en": "…", "ar": "…" } }
```

### الأهداف الكمّية (المرحلة الأولى من المحتوى)

- رفع كل بنك إلى **≥ 150 سؤالًا** (توازن الأوضاع وتقليل التكرار في الجولة الواحدة).
- لكل بنك، ضمان **≥ 30 سؤالًا لكل صعوبة** (easy/medium/hard) حتى تعمل الصعوبة التكيّفية (5.2) والاختيار حسب الصعوبة بسلاسة.
- **لغات:** إضافة لغات ناقصة (مثل Kotlin, Dart, Elixir, Scala, Haskell, Zig) ورفع اللغات النادرة.
- **الإجمالي المستهدف:** ~900 → **~1200+** سؤالًا.

### خطوات التنفيذ

1. **سكربت تحقّق `scripts/validate-questions.js`** (يُشغَّل قبل كل بناء) يفحص:
   - تفرّد `id` داخل كل ملف.
   - وجود `difficulty` ∈ {easy, medium, hard}.
   - اكتمال ثنائي اللغة: `explanation.en` و`explanation.ar` (والـ `question` للصيغتين 2/3) غير فارغة.
   - للصيغة 2: `answer` ∈ `options`، و`options.length ≥ 3`.
   - للصيغة 3: `answer` موجود ضمن `accept`.
   - لا `codeSnippet` مكرّر (كشف نسخ/لصق).
   - إخراج تقرير عدّاد لكل بنك/صعوبة.
2. **تأليف الدُفعات:** إضافة الأسئلة على دفعات لكل بنك، مع مراجعة تقنية (صحّة الكود/الإجابة) قبل الدمج.
3. **ترقيم `id`:** المتابعة من أعلى `id` حالي في كل ملف (تفادي التصادم).
4. **اختبار الدمج:** `electron test/smoke-all.js` (يتحقّق أن الإجمالي = مجموع الأبناك وأن «All» يسحب من الجميع).

### الجهد والمخاطر
- **الجهد:** L (تدريجي — كل دفعة S)، معظمه تأليف ومراجعة.
- **المخاطر:** منخفضة تقنيًا؛ الخطر الوحيد جودة/صحّة السؤال → يعالجه سكربت التحقّق + المراجعة.

### مستقبلًا (اختياري)
- **أسئلة من Supabase:** جدول `questions` + RPC لجلب عشوائي، يتيح إضافة محتوى **بلا إصدار جديد** (حاليًا الأسئلة مضمّنة في الحزمة).
- **مساهمات المجتمع:** نموذج إرسال + مراجعة (يعيد استخدام مسار البلاغات الموجود).

## الاختبار والإطلاق (لكل حزمة)

1. `node --check src/renderer.js`
2. `pnpm run build:web` والتأكد من ختم النسخة على السكربتات.
3. `npx electron --disable-gpu test/smoke-all.js` (يجب 14/14).
4. تحقّق تخطيط في المتصفح الداخلي (قياس `getBoundingClientRect` — لا لقطات).
5. رفع النسخة في `package.json` + كاش `public/sw.js` (`gtl-cache-vN`).
6. commit + push، ثم تأكيد النسخة live عبر `web-shim.js`.
7. لتغييرات السيرفر: `apply_migration` + مرآة في `supabase/schema.sql` + اختبار إدراج.
